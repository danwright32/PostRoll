# PostRoll — Impeccable Design Context

## Design Context

### Users

**One user: Dan Wright.** Solo performing arts photographer (classical concerts, theater, opera, musicals, dance, rock). Uses PostRoll weekly to process one event at a time — upload program PDF, assign photos to posting days, generate captions + blog draft, export. The tool is deeply personal; it handles content Dan already made and must honor the care he put into capturing it.

**Usage context:** At a desk, post-shoot, reviewing images he's proud of. Unhurried, professional, focused. Not a quick utility — more like sitting down at an editing station.

**Job to be done:** Eliminate the weekly Canva/Final Cut/Photoshop/Metricool grind so Dan can spend more time shooting and less time on social content admin.

---

### Brand Personality

**Three words:** Intimate. Editorial. Handcrafted.

The app should feel like working inside a beautifully printed concert program — warm paper, precise typography, personal. Not a startup SaaS product. Not a utility. An extension of Dan's creative practice.

**Signature detail:** Event names appear in SignPainter-HouseScript everywhere they surface — sidebar rows, detail headers, progress screens. This handwritten script creates a direct visual thread between the tool and the assets it generates. The interface IS the output aesthetic.

---

### Aesthetic Direction

**Visual tone:** Warm, editorial, analog-feeling. A photographer's studio — organized, professional, personal.

**Theme:** Light mode only. Forced globally via `NSApplication.shared.appearance = .aqua`. No dark mode, ever.

**Anti-references:** No tech-dashboard feel (not Notion, not Linear, not Figma). No bright accent colors. No system blue. No vibrancy bleed from background windows. No rainbow status colors.

**What it references (implied):** High-end printed concert programs, photography portfolio books, editorial publishing tools like old InDesign layouts. Analog warmth applied to digital UI.

### Color System

| Token | Hex | Use |
|---|---|---|
| `cream` | `#FCFAF7` | Main window / detail background |
| `creamDeep` | `#EDE8E0` | Sidebar, toolbar, secondary surfaces |

| `roseGold` | `#A06A5F` | Primary accent — interactive, active, focus, system accent |
| `roseDeep` | `#7D4E44` | Pressed / active state for rose-gold elements |
| `warmDark` | `#3C3732` | Primary text |
| `warmMid` | `#7A6860` | Secondary text, icons, metadata (4.4:1 on cream — minimum for content) |

**Rose-gold is the ONLY accent color.** All status badges, all interactive states, all focus rings, all dividers — everything bright lives in the rose-gold/warm family. No orange. No system yellow. No green (except the "Exported" stage pill, warm-toned green only).

### Component Language

**BrandTextField / BrandField / BrandTextArea** — cream background, rose-gold 1.5pt strokeBorder on focus, `focusEffectDisabled()` always. Never raw TextField.

**BrandButtonStyle** — rose-gold fill, cream text, 8pt radius, `roseDeep` on press. `easeOut(0.1)` animation on press.

**BrandSectionLabel** — UPPERCASE, SF Pro Medium, 10pt, tracking 1.2. Used above all form groups.

**BrandBanner** — rose-gold left border, warm tinted bg. Tips and warnings. Never orange or system yellow.

**StagePill** — unified warm palette capsule. 7 stages, no rainbow. All warm-toned.

**EventHeader** — SignPainter event name + UPPERCASE roseGold subtitle + RoseGoldDivider. Every detail view starts with this.

**RoseGoldDivider** — 0.5pt, roseGold at 60% opacity. The only divider style.

### System Chrome Overrides

Every default macOS UI pattern that would break the aesthetic is suppressed:

- `focusEffectDisabled()` on all inputs — blue focus ring replaced with rose-gold strokeBorder
- `List(selection:)` removed — manual tap + `roseGold.opacity(0.12)` row background
- `titlebarAppearsTransparent + titleVisibility .hidden` — no macOS chrome
- `fixVibrancy()` on window — prevents sidebar showing other apps
- `NSApplication.shared.appearance = .aqua` — forces light mode everywhere including popovers
- Global accent = rose-gold — tints toggles, DatePicker segments, all AppKit controls

---

### Design Principles

1. **The tool vanishes into the content.** Dan's event names, photos, and copy are the hero. UI chrome should be minimal, warm, subordinate. If a design element draws attention to itself, simplify it.

2. **One accent color, total discipline.** Rose-gold is the single bright color in the system. Never introduce a second accent. When in doubt about a color, go warmer and softer, not brighter.

3. **The interface IS the output.** SignPainter event names in the sidebar echo the generated story covers. The app is designed to feel continuous with the assets it produces — not a separate utility that spits things out.

4. **Override the system where it fights the brand.** macOS defaults (blue focus rings, blue selection, vibrancy bleed, system accent) all break the aesthetic. Always suppress and replace with brand equivalents. Enforce this from the first view.

5. **Editorial precision, not tech polish.** Tight typographic hierarchy, generous whitespace, warm restraint. Not minimalist-startup-bland. Not heavy-chrome-power-tool. The register is a beautifully printed program from a professional arts organization.
